# L3-01 · 后端接口 ggml-backend.h：后端的契约 — 课件说明

> 层：**L3 · 后端发现与注册** ｜ 前置课：`L2-15`

## 学习目标

看完这一课，你应该能：

1. 说出 `ggml_backend_device_i` / `ggml_backend_buffer_type_i` / `ggml_backend_i` 三张虚表各自对应哪一层次（对应验收点）；
2. 说出实现一个新后端最少要实现哪些函数：三张主虚表 9 + 3 + 3 = 15 个必需项，加上数据面 5 个与注册面 3 个共 23 个；
3. 解释为什么 `supports_op` / `supports_buft` / `offload_op` 只存在于设备虚表，而后端级的同名公共 API 被注释标记为"将移除"；
4. 说明 `buffer_type_i.alloc_buffer` 与 `buffer_i` 的分工，以及 `buffer_from_host_ptr` 与 mmap 权重加载（L2-03）的关系；
5. 复述 `iface` + 宿主对象（`iface` / `device` / `context`）的模式，并指出注册面（L3-02）与动态加载（L3-03）从哪里接进来。

## 场景（9 幕）

1. **一个后端，先要签一份契约** — 公共头里没有结构体，只有 7 个不透明句柄：模型代码永远看不到后端的内部。
2. **★ 三张虚表 = 三个层次** — 设备层回答"我是谁、能不能跑"，内存层回答"内存怎么分配"，计算层回答"图怎么算出来"。
3. **★ ggml_backend_device_i：15 个函数指针** — 自我介绍 5 个、创建与内存 4 个、能力判据 3 个、事件 3 个 —— 其中 6 个标了 (optional)。
4. **★ ggml_backend_i：16 个函数指针，必需的只有 3 个** — get_name / free / graph_compute —— 其余 13 个都落在带 (optional) 的注释组里。
5. **buffer type 与 buffer：分配前与分配后** — buffer_type_i 有 6 个函数指针（3 必需），buffer_i 有 11 个（5 必需）；alloc_buffer 把前者变成后者。
6. **公共 API 是虚表的镜像** — 模型代码调的是 ggml_backend_* 系列；它们只是把参数原样转发给某张虚表。
7. **还有一张表：ggml_backend_reg_i（4 个函数指针）** — 一个后端 = 一组设备 + 一个版本号 + 一个可选扩展入口；它是 L3-02 与 L3-03 的接口。
8. **★ 实现一个新后端，最少要填哪些函数** — 按虚表分组数一遍：设备 9 + 计算 3 + 内存类型 3 = 15 个必需项；加上数据面与注册面共 23 个。
9. **把这一课压成一张表** — 五张虚表、52 个函数指针、23 个必需项；契约之外的一切都不用重写。

## 核心结论

### ★ 三张虚表 = 三个层次

| 虚表 | 层次 | 函数指针 | 必需 | 回答的问题 |
|---|---|---|---|---|
| `ggml_backend_device_i` | 设备 | 15 | 9 | 发现与创建 |
| `ggml_backend_buffer_type_i` | 内存 | 6 | 3 | 内存怎么分配 |
| `ggml_backend_i` | 计算 | 16 | 3 | 计算怎么执行 |

另有数据面 `ggml_backend_buffer_i`（11 / 5）与注册面 `ggml_backend_reg_i`（4 / 3）。新后端只要填这几张表，图、张量、调度器都不用改。

### ★ 最少 23 个必需项

按"注释里有没有标 `(optional)`"数：设备 9 + 计算 3 + 内存类型 3 = **15**（三张主虚表）；再加数据面 5 与注册面 3，合计 **23** 个必需项、29 个可留空项。三张主虚表里最能省的是计算层 —— `graph_compute` 之外几乎全是可选项。

### 虚表的形状：iface + 宿主对象

每个 `_i` 结构体只装函数指针（可 `static const` 初始化、零运行时开销）；同名的宿主结构体把虚表放在第一个字段 `iface`，再接上归属关系（`device` / `reg`）与私有 `context`。拿到句柄就等于拿到了虚表 —— 这是整套接口的总模式。

### 契约的边界：能力判据归设备层

`supports_op` / `supports_buft` / `offload_op` 只在 `ggml_backend_device_i` 里；公共头里后端级的同名 API 带着注释 "will be removed, use device version instead"。这解释了后面几课的走向：调度器手里握着的是设备，不是后端（L3-02 / L4 层）。
