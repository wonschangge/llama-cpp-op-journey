## 学习目标

## 场景（8 幕）

1. **量化权重是一串定长块，不是 float 数组** — 一个块覆盖固定个数的元素并自带 scale；张量的字节数 = 块数 × 每块字节数。
2. **★ 18 字节 = 2 字节 scale + 16 字节 4-bit** — QK4_0 = 32：32 个 4-bit 正好 16 字节；再加一个 fp16 的 d，就是 18 字节。
3. **一个类型一个函数：名字里的类型号就是 GGML_TYPE** — ggml-quants.h 把反量化函数按同一套命名排开：dequantize_row_ 加类型名，参数就是对应的 block_ 结构体。
4. **dequantize_row_q4_0：一个字节管相隔 16 的两个元素** — 低 4 位给 y[j]，高 4 位给 y[j + qk/2]，也就是 y[j+16] —— 不是相邻两个。
5. **★ d = max / -8：Q4_0 对称，没有 min** — 先扫一遍求绝对最大 amax（连同它的符号一起记进 max），再算 d 与 id，最后把 x*id 四舍五入加 8 塞进 nibble。
6. **★ Q4_K：144 字节装 256 个权重，12 字节装 16 个 scale/min** — 8 个 32 元素子块共用一个超块头；每个子块的 scale 与 min 都只用 6 bit，8 ×(6+6) = 96 bit 正好 12 字节。
7. **6-bit 的 scale/min 怎么解回来：低位在自己字节，高位从前 4 个字节借** — bytes[0..3] 的低 6 位是 scale 0..3，bytes[4..7] 的低 6 位是 min 0..3；它们的高 2 位被借给 scale/min 4..7，低 4 位放在 bytes[8..11]。
8. **类型号 = 块大小 + 反量化函数** — ggml_type_traits 把三件事绑在一个类型号上：blck_size（多少元素一块）、type_size（一块多少字节）、to_float（怎么还原成 float）。

## 核心结论

### 块大小 = 元素数 + 字节数，两者都由类型号决定

| 类型 | blck_size | type_size | bit / 权重 |
|---|---|---|---|
| Q4_0 | `QK4_0` = 32 | 18 B | 4.5 |
| Q4_1 | `QK4_1` = 32 | 20 B | 5.0 |
| Q8_0 | `QK8_0` = 32 | 34 B | 8.5 |
| Q4_K | `QK_K` = 256 | 144 B | 4.5 |
| Q6_K | `QK_K` = 256 | 210 B | 6.5625 |

字节数不是"元素数 × 位宽 / 8"，而是 `元素数 × 位宽 / 8 + 每块的 scale / min`。正是这个"额外开销"把名义位宽和实际位宽拉开（Q4_0 名义 4 bit，实际 4.5 bit）。

### ★ 同样的 4.5 bit，两种花法

在 256 个权重上，Q4_0 与 Q4_K **都是 144 字节**，而且都恰好是「参数 16 字节 + quants 128 字节」：

```text
Q4_0  8 块 × (d 2B + qs 16B)  =  16B 参数 + 128B quants
Q4_K  1 超块 (dm 4B + scales 12B + qs 128B) = 16B 参数 + 128B quants
```

区别在参数怎么花：Q4_0 是 8 个 fp16 的 scale（每 32 个权重一个），Q4_K 是 2 个 fp16 的超块 scale + 12 字节的 6-bit scale/min（每 32 个权重一个 scale **和**一个 min）。同样的预算换来的是"更细的粒度 + 非对称"。

### 对内核的影响：三件事

1. **访问粒度**：Q4_0 的 `nb[0] = 18`，不是 4 或 16 的整数倍；内核必须按"2 字节 scale + 16 字节 nibble"的节奏走。
2. **位运算开销**：Q4_0 只需 `& 0x0F` / `>> 4`；Q4_K 每个超块还要解 16 个 6-bit 的 scale/min（第 7 幕的移位拼接），这是固定开销。
3. **SIMD 友好度**：Q4_0 的"字节 j 管 y[j] 与 y[j+16]"对 SIMD 不友好，所以 L5-04 的 repack 会把它重排成 4x4 / 4x8 的交错布局；这一步不改数值，只改字节顺序 —— 前提正是本课讲的布局。
