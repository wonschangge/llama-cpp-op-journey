## 学习目标

看完这一课，你应该能：

1. 说出 `struct ggml_tensor` 里哪些字段决定一次内核调用的**形状**（对应验收点）；

3. 判断一个张量是不是**视图**（`view_src != NULL`），并说出它对内存分配的含义；
4. 说明为什么 `enum ggml_type` 的编号**只能追加不能重排**。

## 场景（8 幕）

1. **一个算子，两个面** — 数据面决定"算什么形状、什么精度、数据在哪"；身份面决定"做什么运算"。
2. **结构体的形状被几个 宏钉死** — 这些上限不是随手取的：它们直接决定 struct 的布局，也决定后端内核能假设什么。
3. **★ struct ggml_tensor 逐字段** — 这就是"算子的数据面"的全部。后面所有后端都在读同样这几个字段。
4. **★ ne[] / nb[]：形状与步长** — 源码注释里已经把公式写死了。看懂这三行，就看懂了 ggml 的内存布局约定。
5. **enum ggml_type：精度谱系** — F32/F16/BF16 是浮点，Q*/IQ*/TQ* 是块量化，MXFP4/NVFP4 是新的 microscaling 格式。
6. **三个度量函数：blck_size / type_size / row_size** — 所有内核和分配器都靠这三个函数把"类型 + 形状"换算成字节数。
7. **view_src / view_offs：不拥有数据的算子** — RESHAPE、VIEW、TRANSPOSE、PERMUTE 这些"算子"不产生新数据，只是换一个读法。
8. **把这一课压成一张表** — 数据面 = 4 组字段。记住它们，后面 51 课都在读写这几组。

## 核心结论

### 数据面 = 四组字段

`struct ggml_tensor` 的 12 个字段按用途分成四组：

| 组 | 字段 | 决定什么 |
|---|---|---|
| 身份/精度 | `type` `op` `op_params` `flags` | 后端选哪个 kernel |
| 形状/步长 | `ne[4]` `nb[4]` | 内核怎么访问数据 |
| 位置 | `buffer` `data` `extra` | 数据在哪个设备上 |
| 连接/视图 | `src[10]` `view_src` `view_offs` | 图的结构与零拷贝 |

### ★ nb[] 是 type 的函数

三条不变量（源码注释里写死的）：

```text
nb[0] = ggml_type_size(type)
nb[1] = nb[0] * (ne[0] / ggml_blck_size(type)) + padding
nb[i] = nb[i-1] * ne[i-1]
```

**换类型就换步长，换步长就换内核。** 这是后面 L1-04（块布局）、L5-03（向量化）、L5-04（repack）三课的共同前提。

### 视图算子不拥有数据

`RESHAPE` / `VIEW` / `TRANSPOSE` / `PERMUTE` 只改 `ne[]`、`nb[]` 与 `view_src`/`view_offs`，不复制数据。L4-01 的分配器据此跳过分配 —— 这是 ggml 能在有限显存里跑大模型的原因之一。
