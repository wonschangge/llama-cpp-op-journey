## 学习目标

看完这一课，你应该能：

4. 判断一个张量是不是视图，并说出分配器对视图的两种处理（跳过分配 / 接管源张量地址）；
5. 说明图重放时 `ggml_gallocr_alloc_graph` 为什么可以不重新规划，以及多 buffer 时为什么不行。

## 场景（10 幕）

1. **内存规划发生在建图之后、执行之前** — ggml-alloc.h 的注释把标准用法写死了：选 buffer 类型 -> 预留 -> 分配 -> 查大小 -> 执行。
2. **★ 只进不退的分配器 活不过一张图** — ggml_tallocr 是最简单的分配器：一个 buffer、一个 offset，只往前走；它没有配套的释放函数。
3. **★ free_block：复用靠的就是这张空闲表** — 动态分配器不记录"哪些张量在"，只记录"哪些字节是空的" —— 于是张量之间可以直接换手。
4. **★ best-fit：从空闲表里挑最小够用的那块** — 注意循环上界那个减一：最后一个空闲块不参与挑选，因为它是"可以向外扩"的边界。
5. **还块：与相邻空闲块就地合并** — 张量用完只是把地址还给空闲表；不合并的话，空闲表很快会被碎片塞满（上限 256 块）。
6. **★ 第一趟：先数清谁还要用我** — 分配之前，先把每个张量被引用几次（n_children）、被几个视图指着（n_views）数出来。
7. **★ 第二趟：按拓扑序分配，用完就还** — a -> mul_mat -> add -> out 这张小图跑一遍，看内存怎么在四个格子之间换手。
8. **视图：跳过分配，必要时连地址一起接管** — 判据只有一行：view_src 非空就不进分配分支；能复用的时候连父张量那格都省下来。
9. **★ 图没变，就不重新规划** — alloc_graph 先问 needs_realloc：节点数、叶子数、每个张量的大小都没变，就直接用上次的规划落位。
10. **内存规划的输出，与这一课的一张表** — get_buffer_size 报出的那个数，就是这张图的执行缓冲大小；多 buffer 时按 buffer 分别报。

## 核心结论

### ★ 为什么必须自己管理内存

因为**生命周期在建图时就已知**。图的拓扑序（L1-03）给出了每个张量的"出生"与"死亡"，于是分配器可以：先数一遍谁还要用谁（`n_children` / `n_views`），再沿拓扑序分配，并在计数归零时立刻把地址还给空闲表。

```text
逐个分配的内存账  = 所有张量大小之和
规划后的内存账    = 同时存活张量的峰值
```

线性分配器 `ggml_tallocr` 只有一个单调递增的 `offset`（第 87 行），没有还块路径，所以它只能算前者。这就是 `ggml-alloc.c` 存在的理由。

### ★ 复用的三个动作

| 动作 | 实现 | 位置 |
|---|---|---|
| 取块 | best fit：装得下且最小 | `ggml_dyn_tallocr_alloc`，202-224 |
| 还块 | 与相邻空闲块就地合并 | `ggml_dyn_tallocr_free_bytes`，311-350 |
| 原地 | 同 layout 且父张量只剩一个消费者时直接换手 | `ggml_gallocr_allocate_node`，651-677 |

第三个动作是"零字节"的：`y = add(h, c)` 的输出直接住在 `h` 的地址上。

### 视图的两条规则

判据是 `view_src != NULL`（`ggml_impl_is_view`）。于是：

1. **跳过分配**：`ggml_gallocr_allocate_node` 的第一行判断就把它排除在外（第 627 行）；
2. **单独计数**：视图给源张量加的是 `n_views` 而不是 `n_children`（第 739-742 行），两个计数同时归零才允许释放。

这补上了 L1-01 的另一半：视图不复制数据，而且**视图链上的地址可以在算子之间整块转让**。

### 代价：图变了就得重规划

`ggml_gallocr_needs_realloc`（1009-1050）逐节点比对图形态与规划时记录的 `size_max`。变了以后：单 buffer 由 `ggml_gallocr_alloc_graph` 自动重规划（第 1058 行），**多 buffer 直接返回 false**（第 1061-1065 行），要求调用方先调 `ggml_gallocr_reserve_n` —— 因为节点该进哪个 buffer 是调度器的决定，不是分配器能猜的。

这正是 L4-02 的入口：调度器负责切分与 buffer 归属，分配器负责在给定归属下把地址排到最紧。
