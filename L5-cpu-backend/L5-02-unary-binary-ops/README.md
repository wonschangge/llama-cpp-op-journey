## 学习目标

看完这一课，你应该能：

1. 说出 unary op 的 SIMD 分发是怎么做的（对应验收点）——包括"哪一层分派、SIMD 在哪一层进来"；

3. 说出二元算子里连续路径与广播路径的区别，以及广播是怎么用取模实现的；
4. 说出 DUP / ADD 遇到量化类型时走的不同路径，并指回 L1-04 的块布局。

## 场景（10 幕）

1. **一元与二元：CPU 后端里最规整的一族** — 23 个一元内核 + 4 个二元入口，共用同一套写法；本课把它们拆到模板层。
2. **★ 第一层分派：op 名 -> 函数名** — ggml_compute_forward_unary 只做一件事：从 dst 里读出是哪个一元 op，然后 switch 到同名函数。
3. **★ 第二层分派：函数指针模板 x 类型对** — unary_op 把"做哪个运算"变成模板参数；5 条 if-else 把"(src0 类型, dst 类型)"变成模板实参。
4. **★ 为什么这一族最容易向量化：平凡循环 + 行指针** — 内层循环一次只碰一个元素、只依赖 x[i] —— 没有归约、没有跨元素依赖，编译器可以放手展开成 SIMD。
5. **★ 两条 SIMD 路线：编译器 vs 手写 vec_ 内核** — GELU 家族与 SILU 仍在 ops.cpp：它们调用 ggml_vec_* 手写内核，按编译期 ISA 宏分支。
6. **同一套展开，在 ops.cpp 里再来一份：DUP 的类型对表** — DUP 要支持"任意非量化类型 -> 任意非量化类型"，于是模板实参从 2 个变成 (src_t, dst_t)。
7. **二元算子：连续 与 广播 两条循环** — 两个输入形状相同时指针同步走；src1 更小时用 i % ne10 回绕 —— 这就是广播。
8. **★ 二元的 7 条类型链，和唯一的 vDSP 例外** — binary_op 有 7 条类型分支；Accelerate 构建里还会按 op 指针挑一个 vDSP 函数。
9. **三个特例：ADD1（标量）、SCALE（参数）、WIN_PART（窗口）** — 同样是逐元素，输入却可以来自标量张量、op_params、或一个滑动的窗口原点。
10. **把这一课压成一张表** — 三层分派 + 两条 SIMD 路线。验收点："unary op 的 SIMD 分发是怎么做的"。

## 核心结论

### ★ unary op 的 SIMD 分发：分派是编译期的，向量化有两条来源

| 层 | 机制 | 在哪 |
|---|---|---|
| op -> 函数 | `switch (ggml_get_unary_op(dst))`，22 个 case | `ops.cpp:10137` |
| 函数 -> 模板实例 | `unary_op<op_abs>`，op 是函数指针模板参数 | `unary-ops.cpp:136` |
| 类型对 -> 特化 | 5 条 if-else -> `apply_unary_op<op, s0, d>` | `unary-ops.cpp:140` |
| 向量化（新族，18 个） | 平凡循环，编译器自动向量化（实测 `vandps ymm`） | `unary-ops.cpp:105` |
| 向量化（老族，4 个） | 调 `ggml_vec_*`，按编译期 ISA 宏分支 | `ops.cpp:2611` / `vec.cpp:380` |

**关键结论**：`unary-ops.cpp` / `binary-ops.cpp` 里 `ggml_cpu_has_*` 出现 0 次 —— 这一族**没有运行时的 SIMD 分发**。新族把向量化交给编译器，老族交给编译期宏。真正"按 CPU 特性选 kernel"的分派在 L5-04（traits / repack）与 L5-05（多架构内核）。

### 类型 x 运算的笛卡尔积是手写的

模板只写一次，实例化却是逐条手写的 if-else 链：一元 5 条类型对，二元 7 条，DUP 是一个 `switch (src0->type)` 里再嵌 4 条分支。

代价是源码冗长与二进制体积（实测 `unary-ops.cpp` 单翻译单元 `.text` = 87060 字节），收益是**零运行时开销**：类型对在编译期定下来，循环里没有类型判断。源码里两处 TODO 都指向同一个未来方向 —— 改用 traits 查表。

### 二元算子：广播就是重算指针

两个输入形状相同走 `vec_binary_op_contiguous`（三个指针同步走）；src1 更小时走 `vec_binary_op_non_contiguous`，用 `i10 = i % ne10` 回绕。合法性由 `ggml_can_repeat` 断言把关（形状规则在 `ggml.c`，内核只负责相信它）。

这一步的跨课呼应：**内核永远假设"形状已经检查过、内存已经分配好"** —— 这是 L1（形状/步长）、L4（分配与调度）与 L5（内核）之间那条清晰的分界线。
